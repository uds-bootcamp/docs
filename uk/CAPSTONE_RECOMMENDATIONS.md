# Рекомендації щодо випускних проєктів

### 1. Основні принципи ефективного випускного проєкту

Успішний випускний проєкт повинен дотримуватися наступних принципів:

* **Демонструвати основні компетенції:** Проєкт повинен яскраво демонструвати основні технології та методології, викладені в буткемпі (наприклад, конкретний фронтенд-фреймворк, бекенд-мова, система баз даних або бібліотека для аналізу даних).
* **Вирішувати нетривіальну проблему:** Уникайте загальних проєктів, таких як базовий список справ, калькулятор або додаток погоди, якщо не впроваджено унікальний та складний набір функцій. Проєкт, що вирішує конкретну, реальну проблему для нішевої аудиторії, є більш переконливим.
* **Бути орієнтованим на дані:** Додаток повинен бути побудований навколо створення, маніпулювання або представлення даних. Це може бути досягнуто через контент, створений користувачами, інтеграцію із зовнішніми API або аналіз існуючого набору даних.
* **Мати керований обсяг:** Визначте Мінімальний життєздатний продукт (MVP), який можна досягти протягом часових рамок буткемпу. Амбітні функції можуть бути перелічені як "цілі розширення" для впровадження, якщо дозволить час. Це демонструє навички планування та встановлення пріоритетів.

### 2. Рекомендації щодо проєктів за спеціалізацією

Наступні ідеї категоризовані за загальними треками буткемпу. Кожна розроблена так, щоб бути масштабованою від базового MVP до більш складного додатку.

#### Приклад: Data Science / Data Analytics

Ці проєкти підкреслюють наскрізний робочий процес з даними: отримання даних, очищення, дослідницький аналіз даних (EDA), моделювання та візуалізація/інтерпретація.

* **Прогностичне моделювання для бізнес-проблеми:**
    * **Концепція:** Використовуйте публічний набір даних (з таких джерел, як Kaggle, UCI Machine Learning Repository або урядові портали) для побудови моделі, яка прогнозує конкретний результат.
    * **Приклади проблем:** Прогнозування відтоку клієнтів для телекомунікаційної компанії, прогнозування продажів для роздрібного набору даних, класифікація заявок на кредит як схвалених/відхилених.
    * **Процес:**
        1.  **Очищення даних та EDA:** Документуйте процес обробки відсутніх значень, викидів та виконання інжинірингу ознак. Використовуйте візуалізації для виявлення інсайтів.
        2.  **Побудова моделі:** Впровадьте та порівняйте декілька моделей машинного навчання (наприклад, Логістична регресія, Random Forest, Gradient Boosting).
        3.  **Оцінка:** Використовуйте відповідні метрики (наприклад, Точність, Precision, Recall, F1-score, AUC-ROC для класифікації; $R^2$, RMSE для регресії) та крос-валідацію для оцінки продуктивності моделі.
        4.  **Інтерпретація:** Поясніть результати, важливість ознак та бізнес-наслідки моделі.
    * **Демонстрація технологій:** Демонструє володіння Python/R, бібліотеками, такими як Pandas, NumPy, Scikit-learn, та інструментами візуалізації даних (Matplotlib, Seaborn). Результатом зазвичай є Jupyter Notebook або детальний звіт.

* **Інтерактивна панель візуалізації даних:**
    * **Концепція:** Створіть веб-панель, що базується на інтерактивності, для дослідження складного набору даних. Метою є надання користувачам можливості виявляти власні інсайти.
    * **Приклади наборів даних:** Тенденції глобального споживання енергії, дані про продуктивність громадського транспорту міста, аналіз ринку нерухомості.
    * **Основні функції MVP:** Декілька пов'язаних діаграм та графіків, фільтри, що дозволяють користувачам поглиблюватися в дані (наприклад, за діапазоном дат, регіоном, категорією).
    * **Інструменти:** Можна побудувати використовуючи бібліотеки Python, такі як Plotly Dash або Streamlit, або з інструментами BI, такими як Tableau або Power BI (якщо охоплено в навчальній програмі).
    * **Демонстрація технологій:** Підкреслює розповідь даними, навички обробки даних та здатність створювати зручні для користувача інтерфейси для дослідження даних.

* **Аналіз обробки природної мови (NLP):**
    * **Концепція:** Застосуйте техніки NLP до корпусу текстових даних для вилучення значення.
    * **Приклади проєктів:** Аналіз настроїв відгуків на продукти з сайту електронної комерції (скрепінг або через API), тематичне моделювання колекції новинних статей для виявлення ключових тем, розпізнавання іменованих сутностей (NER) у юридичних документах.
    * **Процес:** Отримання тексту (скрепінг/API), очищення тексту (видалення стоп-слів, стемінг/лематизація), векторизація (TF-IDF, Word2Vec) та застосування відповідної NLP моделі.
    * **Демонстрація технологій:** Демонструє навички у високозатребуваній підгалузі data science з використанням бібліотек, таких як NLTK, spaCy або transformers.

### 3. Систематична структура виконання проєкту

1.  **Ідея (1-2 дні):** Проведіть мозковий штурм 3-5 ідей на основі особистих інтересів або проблем, з якими ви стикалися.
2.  **Аналіз можливості (1-2 дні):** Для кожної ідеї перевірте наступне:
    * **Технічна відповідність:** Чи використовує проєкт технології, викладені в буткемпі?
    * **Доступність даних:** Чи є надійний та доступний API або набір даних? Перегляньте документацію та ліміти швидкості.
    * **Часові рамки:** Чи може MVP бути завершений приблизно за 60-70% відведеного часу проєкту?
3.  **Визначення обсягу та планування (2-3 дні):**
    * Виберіть найбільш життєздатну ідею.
    * Напишіть формальну пропозицію проєкту, що окреслює постановку проблеми, цільового користувача, основні функції MVP та список пріоритетних цілей розширення.
    * Використовуйте інструмент управління проєктами (наприклад, Trello, Jira, GitHub Projects) для розбиття MVP на невеликі, дієві завдання (наприклад, "Налаштувати схему бази даних", "Створити компонент входу користувача", "Впровадити API кінцеву точку для отримання продуктів").
4.  **Виконання та представлення:**
    * **Контроль версій:** Використовуйте Git для контролю версій з першого рядка коду. Робіть коміти часто з чіткими, описовими повідомленнями.
    * **Документація:** Підтримуйте вичерпний файл `README.md` у вашому репозиторії GitHub. Він повинен включати опис проєкту, інструкції з налаштування та підсумок використовуваних технологій.
    * **Розгортання:** Розгорніть додаток на живому сервері (наприклад, Vercel, Netlify для фронтенду; Heroku, AWS для бекенду). Живий, функціонуючий проєкт є критичною вимогою для огляду портфоліо.
    * **Кейс-стаді:** Створіть детальне кейс-стаді на веб-сайті вашого портфоліо або як допис у блозі. Опишіть проблему, ваш процес, технічні виклики, з якими ви зіткнулися, та рішення, які ви впровадили. Ця розповідь є настільки ж важливою, як і сам код.
