# Рекомендації щодо випускних проєктів

### 1. Ключові принципи ефективного випускного проєкту

Успішний випускний проєкт має відповідати таким принципам:

* **Демонстрація ключових компетенцій:** Проєкт має яскраво демонструвати основні технології та методології, опановані під час буткемпу (наприклад, конкретний фронтенд-фреймворк, бекенд-мова, система баз даних або бібліотека для аналізу даних).
* **Розв'язання нетривіальної задачі:** Уникайте шаблонних проєктів, таких як базовий список завдань (to-do list), калькулятор або застосунок погоди, якщо він не має унікального та складного набору функціональності. Проєкт, що розв'язує конкретну, реальну задачу для нішевої аудиторії, виглядає більш переконливо.
* **Орієнтація на дані:** Застосунок має бути побудований навколо створення, обробки або презентації даних. Цього можна досягти через контент, згенерований користувачами, інтеграцію із зовнішніми API або аналіз наявного набору даних.
* **Керований обсяг (scope):** Визначте **Мінімально життєздатний продукт (MVP)**, який реально створити в межах часових рамок буткемпу. Амбітні можливості (features) можна зазначити як "додаткові цілі" (stretch goals) для реалізації, якщо вистачить часу. Це демонструє навички планування та пріоритизації.

### 2. Рекомендації щодо проєктів за спеціалізацією

Наведені нижче ідеї категоризовано за основними напрямами буткемпу. Кожна ідея розроблена так, щоб її можна було масштабувати від базового MVP до складнішого застосунку.

#### Приклад: Data Science / Data Analytics

Ці проєкти охоплюють повний (end-to-end) робочий процес із даними: отримання даних, їх очищення, дослідницький аналіз (EDA), моделювання та візуалізацію/інтерпретацію.

* **Прогностичне моделювання для бізнес-задачі:**
    * **Концепція:** Використовуйте публічний набір даних (dataset) (із таких джерел, як Kaggle, UCI Machine Learning Repository або урядові портали), щоб побудувати модель, яка прогнозує конкретний результат.
    * **Приклади задач:** Прогнозування **відпливу** клієнтів для телекомунікаційної компанії, прогнозування продажів для набору роздрібних даних, класифікація кредитних заявок (схвалено/відхилено).
    * **Процес:**
        1.  **Очищення даних та EDA:** Документуйте процес обробки **пропущених** значень, **викидів (outliers)** та **створення/відбору ознак (feature engineering)**. Використовуйте візуалізації для пошуку інсайтів (висновків).
        2.  **Побудова моделі:** Реалізуйте та порівняйте декілька моделей машинного навчання (наприклад, Логістична регресія, **Випадковий ліс (Random Forest)**, **Градієнтний бустинг (Gradient Boosting)**).
        3.  **Оцінювання:** Використовуйте доречні метрики (наприклад, **Accuracy**, Precision, Recall, F1-score, AUC-ROC для класифікації; $R^2$, RMSE для регресії) та **перехресну валідацію (cross-validation)** для оцінювання якості моделі.
        4.  **Інтерпретація:** Поясніть результати, **важливість ознак (feature importance)** та **бізнес-висновки** з моделі.
    * **Демонстрація технологій:** Демонструє володіння Python/R, бібліотеками, такими як Pandas, NumPy, Scikit-learn, та інструментами візуалізації даних (Matplotlib, Seaborn). Результатом зазвичай є Jupyter Notebook або детальний звіт.

* **Інтерактивна панель візуалізації даних (Дашборд):**
    * **Концепція:** Створіть інтерактивну веб-панель (дашборд) для дослідження комплексного набору даних. Мета — надати користувачам можливість самостійно знаходити інсайти.
    * **Приклади наборів даних:** Тенденції глобального споживання енергії, дані про роботу громадського транспорту міста, аналіз ринку нерухомості.
    * **Ключові можливості MVP:** Декілька взаємопов'язаних діаграм та графіків, фільтри, що дозволяють користувачам **деталізувати** дані (наприклад, за діапазоном дат, регіоном, категорією).
    * **Інструменти:** Можна створити з використанням бібліотек Python, таких як Plotly Dash або Streamlit, або за допомогою BI-інструментів, таких як Tableau чи Power BI (якщо їх вивчали у програмі).
    * **Демонстрація технологій:** Демонструє навички **сторітелінгу на основі даних (data storytelling)**, обробки даних та вміння створювати зручні (user-friendly) інтерфейси для дослідження даних.

* **Обробка природної мови (NLP):**
    * **Концепція:** Застосувати техніки NLP до корпусу текстових даних для видобування корисної інформації.
    * **Приклади проєктів:** **Аналіз тональності (sentiment analysis)** відгуків на продукти з сайту електронної комерції (отриманих шляхом **скрейпінгу** або через API), **тематичне моделювання (topic modeling)** колекції новинних статей для виявлення ключових тем, розпізнавання іменованих сутностей (NER) у юридичних документах.
    * **Процес:** Отримання тексту (скрейпінг/API), очищення тексту (видалення стоп-слів, стемінг/лематизація), векторизація (TF-IDF, Word2Vec) та застосування доречної NLP-моделі.
    * **Демонстрація технологій:** Демонструє навички у затребуваній підгалузі Data Science з використанням бібліотек, таких як NLTK, spaCy або transformers.

### 3. Систематична структура виконання проєкту

1.  **Генерація ідей (1-2 дні):** Проведіть мозковий штурм (brainstorming) 3-5 ідей на основі особистих інтересів або задач, з якими ви стикалися.
2.  **Аналіз можливостей (1-2 дні):** Для кожної ідеї перевірте таке:
    * **Технічна відповідність:** Чи використовує проєкт технології, що вивчалися на буткемпі?
    * **Доступність даних:** Чи є надійний та доступний API або набір даних? Перегляньте документацію та **ліміти запитів (rate limits)**.
    * **Часові рамки:** Чи можна завершити MVP приблизно за 60-70% відведеного на проєкт часу?
3.  **Визначення обсягу та планування (2-3 дні):**
    * Оберіть найбільш життєздатну ідею.
    * Напишіть **формалізований опис** проєкту, де окреслено **постановку задачі**, цільового користувача, **ключові можливості** MVP та **пріоритезований** список **додаткових цілей**.
    * Використовуйте інструмент для управління проєктами (наприклад, Trello, Jira, GitHub Projects), щоб розбити MVP на невеликі, конкретні завдання (tasks) (наприклад, "Налаштувати схему БД", "Створити компонент логіну", "**Реалізувати** API-ендпоінт для отримання продуктів").
4.  **Виконання та презентація:**
    * **Контроль версій:** Використовуйте Git з першого рядка коду. Робіть коміти (commits) часто, з чіткими, **змістовними** повідомленнями.
    * **Документація:** Ведіть вичерпний файл `README.md` у вашому репозиторії GitHub. Він повинен містити опис проєкту, інструкції з **налаштування (setup)** та **перелік** використаних технологій.
    * **Розгортання (Deployment):** Розгорніть **застосунок** на реальному сервері (наприклад, Vercel, Netlify для фронтенду; Heroku, AWS для бекенду). **Наявність** **працюючого** проєкту є критичною вимогою для портфоліо.
    * **Кейс (Case Study):** Створіть детальний **опис проєкту (кейс)** на своєму сайті-портфоліо або у вигляді допису в блозі. Опишіть задачу, ваш процес, технічні виклики, з якими ви зіткнулися, та рішення, які ви реалізували. Ця описова частина є такою ж важливою, як і сам код.
